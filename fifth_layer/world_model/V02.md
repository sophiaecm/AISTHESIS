# World model v0.2: deterministic multi-hypothesis reasoning

Opt-in only. Existing production reasoners and live_app do not import this
layer. Providers read already computed outputs; they never call reasoners,
models, experience memory, evaluation or learning. No sensory fusion is added.

```python
from fifth_layer.world_model import (
    WorldStateAdapter, collect_evidence, MultiHypothesisGenerator,
    adapt_temporal_trajectories,
)

scene = WorldStateAdapter.from_world_state(world_state, scene_id="scene-42")
# temporal_output is an already computed ExpectedConsequences, FutureState,
# LatentState, or corresponding plain mapping. No output is computed here.
bundle = collect_evidence(scene, temporal=temporal_output,
                          source_timestamps={"temporal": scene.timestamp})
hypotheses = MultiHypothesisGenerator().generate(scene, bundle, horizon_seconds=3.)
trajectories = adapt_temporal_trajectories(scene, bundle, hypotheses)
weights = hypotheses.normalized_posteriors
```

## Evidence contracts and providers

EvidenceItem stores stable ID, scene ID, source category/component, evidence
type, structured value, optional source confidence/timestamp, support/opposition
tags, track/object ID and provenance. None confidence means unassessed, not zero
probability. EvidenceBundle validates scene consistency and unique IDs, sorts
by stable ID, and freezes all nested values. Direct construction rejects visual
buffers; providers sanitize summaries using the v0.1 immutable boundary.

Providers accept ExpectedConsequences.predictions, FutureState.data,
LatentState.features, or the equivalent mapping. No wrapper carries a source
timestamp, so callers can supply one; otherwise the scene timestamp is used.
An explicit record timestamp (or inherited observation_timestamp for physics /
temporal outputs) takes precedence. All original timestamps and
selected fields remain in values/provenance. Unknown scene timestamp remains
None in evidence; generation requires an explicit created_timestamp in that case.

| Provider/source | Actual selected fields and interpretation |
| --- | --- |
| PhysicsReasoner | position, velocity, dt, occlusion_zone, expected_next_position, enters_occlusion_zone, hidden_interaction_possible, latent_physical_risk; explicit enters_occlusion_zone=True supports possible occlusion |
| Existing physics inputs in SceneState | physics_hidden_interaction_possible, physics_confidence; preserved without inventing an actor |
| TemporalPredictionReasoner | track_id, motion_state, current_center, velocity_x/y, trajectory, trajectory_available, prediction_basis, expected_motion_continuation, occlusion_prediction, raw_confidence, predicted_event |
| OcclusionReasoner | occlusion_hypotheses entries: object_id, class_name, hypothesis, occlusion_probability; possible/likely labels support occlusion, but probability is never relabelled confidence |
| extract_occlusion_evidence | occlusion_evidence records; overlap supports occlusion, raw frame truncation alone does not |
| Orchestrator's existing exported context | SceneState.occlusion_evidence.occlusion_reasoning.expected.occlusion_hypotheses |
| extract_semantic_evidence | description_available, mentioned_objects/actions/relations, semantic_text; preserved as unbound context, not parsed again |
| SemanticConflictReasoner | semantic_conflicts entries; preserved as reported description discrepancies, never converted into negative physical evidence |
| extract_motion_evidence | motion_evidence entries including current_object_id, track_id, motion_state and geometry/velocity |
| TrackMemory | observed_objects and predicted_tracks remain labelled separately; explicit predicted, possibly occluded track supports cautious reappearance |

collect_evidence uses supplied provider outputs when present, otherwise the
corresponding SceneState summaries; temporal output must be supplied explicitly.
Motion and tracking always read the scene. Identical evidence IDs are merged
without increasing confidence. No claims about collision, support loss, falling,
or a newly hidden actor are implemented: the current sources do not provide
the required physical/semantic association for those rules.

Provenance stores actual source container and selected field paths, source
timestamp, original SceneState provenance, provider component and adapter 0.2.
Known raw source confidence is copied; occlusion probabilities and pixel
uncertainty remain in values with their original names and units.

## Rules and association

Evidence support/opposition tags name candidate categories. The generator
recognizes only the four concrete categories below, plus its unknown fallback.
Manual EvidenceItems can supply explicit contradictory tags with source provenance.

1. continued_motion: a recognized moving motion_state (moving, moving_right,
   moving_left, moving_up, moving_down). Stationary evidence opposes it.
2. object_stops: stationary evidence directly supports stopping/remaining still.
   Moving evidence also permits a lower-ranked stop alternative with an explicit
   assumption that motion could change. Moving evidence opposes this candidate;
   it can therefore be both the premise for an alternative and counterevidence.
3. object_becomes_occluded: overlap/possible occlusion evidence, an explicit
   physics enters_occlusion_zone, or temporal approaching_occlusion /
   occlusion_interaction_possible. This concerns existing content, not a new actor.
4. object_reappears: an explicitly predicted track marked possible_occlusion,
   or motion plus occlusion attached to the same explicit identity. Persistence
   while hidden is an assumption, never an observation or guaranteed emergence.
5. unknown_dynamic_event: no recognized rule for an evidence association, or an
   empty bundle. Missing evidence is not attached as evidence_against.

Candidates merge by scene, association and category. Association uses track ID,
otherwise object_id/current_object_id within the supplied scene. Numeric and
string IDs remain distinct. Class names and unbound reports never join objects:
each unbound evidence item has its own scope. Providers do not recover track IDs
by indexing filtered detections or matching class names. Callers must preserve
the original object-index namespace when supplying legacy evidence.

All generated hypotheses start active, including unknown alternatives. They carry
evidence_for/against IDs, named rule, assumptions, original score inputs and
source confidence traceability. Semantic mentions cannot manufacture child/actor
claims. Absence of a description match is not contradiction. Uncertainty stays
explicit and does not trigger probability arithmetic or change observations.

## Exact heuristic scoring policy

- Direct candidate base score: 1.0.
- Stop alternative inferred from moving evidence: 0.25.
- Unknown candidate base score: 0.0.
- One or more explicit opposing items multiply the base score by 0.5 once.
  Evidence count never compounds this factor or increases support score.
- prior_probability is 0.5 for every candidate: a neutral heuristic placeholder,
  not an empirical prior or an exclusive distribution.
- posterior_probability holds the above raw compatibility score solely to use
  the v0.1 contract. It is **not a calibrated or Bayesian probability**.
- HypothesisSet.normalized_posteriors alone normalizes active scores. All-zero
  scores use the existing uniform fallback. These are ranking weights, not
  calibrated likelihoods; an unknown singleton's weight 1 does not mean certainty.
- Hypothesis confidence copies the first supporting item with known confidence
  in stable evidence-ID order, recording that source ID. If none exists it uses
  v0.1's numeric placeholder 0 with confidence_assessed=False. No averaging occurs.

For a single moving record, continued_motion scores 1.0 and object_stops scores
0.25 * 0.5 = 0.125. Both survive. Scores, prior policy, confidence source and every
raw input are recorded; memory, risk and uncertainty do not modify these scores.

## Trajectories and determinism

The temporal adapter copies supplied trajectory point dictionaries and centers
only to their supporting continued_motion hypothesis. It never synthesizes a
bbox, uncertainty, or point. It includes source points within the requested
horizon and only when source issuance timestamp equals hypothesis creation time;
stale trajectories are not retimed. Empty/unavailable/incompatible sources yield
no trajectory. IDs and source evidence linkage are retained in provenance and
validated against HypothesisSet. No path is assigned to stop/reappearance claims.

IDs use SHA-256 over canonical structured inputs. Hypothesis IDs identify scene,
association, category, creation time and horizon; changing evidence scores can
revise the same candidate identity. Evidence IDs include content and provenance.
Bundle input permutation cannot alter ordering, rule scores, IDs or links. No
wall-clock reads or random numbers are used. Supply a stable scene ID through
WorldStateAdapter when reproducibility across separate conversions is required.
